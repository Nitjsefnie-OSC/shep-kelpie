# Triage's spam check

The classifier an issue goes through after its limits and before its research call (#895): the settings, the port, what a hit does and what a failure does. The settings and pick rule are in `triage.md`, the pass itself in `triage-pass.md`, the author's round in `triage-author.md`.

- `[app.dogs.kelpie.triage.spam]`, an absent table meaning no check, with `deny_unknown_fields`. `src/settings/triage.rs`
  - `gateway`: a gateway named in kelpie's own `[gateways.<name>]`. Absent means no check at all. `Gateways::check_triage_spam` refuses a start, a `reread` and a `shep kelpie set` whose gateway kelpie's settings lack or cannot dial, naming `triage.spam.gateway`. A gateway whose key is unset is not refused there either: kelpie cannot ask it, so the check is off for the run and told once, and the runner starts. `src/settings/gateway.rs`, `src/runner.rs`, `src/runner/reread.rs`, `src/flock/set.rs`
  - `path`: the route its classifier is served on, such as `/classify`. `ClassifierPath` refuses one that is not a single path: it needs a leading `/` and holds no control character, no space and no `#`, each of which would put a line of its own in the request. `Triage::check` refuses `gateway` with no `path`, naming `triage.spam.path`.
  - `threshold`: default 0.8. `Probability` is a `#[serde(try_from = "f64")]` newtype held in thousandths, so it is `Eq` and comparable and a threshold is met by an exact comparison and not a float one. A value outside 0 to 1 is refused naming `triage.spam.threshold`. It is written back as the number it stands for.
- The question is the one yes/no question `spam`: "Is this issue spam, an advertisement, or text unrelated to the project?" The request is the gateway's classifier shape: a `state` of the issue's title, its body cut as `max_body_kb` cuts it for the call, `author_association` and the account's age in days, the last two `null` when the forge cannot say, and `questions` holding that one question. The answer is the probability it is spam, read from `answers` under the question's name or from the name at the top level; a number outside 0 to 1 is no answer. `src/adapters/classifier.rs`
- It is a port, `Classifier`, so a test answers it in memory (`src/test/classifier.rs`) and no triage test reaches a gateway. The gateway's address and key come from `Gateways::upstream`, the same `Upstream` every other gateway call is made with, and the request goes through `paddock::send`. `src/ports/classifier.rs`
- It is asked after the four limits, so an issue a limit held costs no classifier call, and the maintainer's own issues and one `shep kelpie triage` asked for skip it, on the same flag that skips the limits. `src/runner/triage.rs`, `src/runner/triage/spam.rs`
- At or above `threshold` the issue gets `possible-spam`, made on a repo that lacks it, and nothing else: no comment, no research call, no close, no lock and no hide. Kelpie never decides that an issue is spam on the maintainer's behalf; the label is the ask. Its record is `done` with `spam` the probability (state version 70) and no call, so it spends no place of `per_day` or `per_author_per_day`, and `status` says it. `possible-spam` joins `TRIAGE_LABELS`, so the pick rule leaves it alone, and `triage_ask` lets the verb through the label: the verb is how the maintainer overrules the check. `src/state/triage.rs`, `src/runner/triage.rs`, `src/flock/control/plain.rs`
- Below the threshold the pass goes on as it was.
- A gateway that cannot be reached, that refuses, or whose key kelpie's environment does not hold, is told once and turns the check off for the rest of the run, so an outage costs one attempt and not one timeout per issue; the next start asks again. The pass goes on without the check and the limits still hold, so an outage opens no flood. `src/runner/triage/spam.rs`
- Each check that got an answer is a ledger line of its own: role `triager`, kind `spam-check`, the issue, no tokens, no cost, no session and no harness. It is no `triage` line, so it moves no role total in `usage` and spends no place of a cap. A check that got no answer is not on the ledger. `src/usage.rs`
- It is no model call in kelpie's counting: no session, no harness, no lease, no slot, no work item record, and no call the caps count.
