# Agent files

The agent file, the shipped agents and how a file builds on one. Harnesses, gateways and the agent settings are in agents.md.

- Agent = `<name>.md`, YAML frontmatter tagged `role` + Markdown body; bad file stops runner naming file + line. serde-saphyr (serde_yaml archived). ADR 0006, #313
- Reread each wake (edits land live). Item keeps its agent, runs the file as it is now. #313
- `extends` merges frontmatter keys as text before parsing (every check applies); parameters on a reference refused (each a new label + ledger key). #386, `crates/core/src/agents/extends.rs`
- Shipped agents are kelpie's own, embedded from `agents/`; whole agents in `DEFAULTS`, baselines in `crates/core/src/agents/baseline.rs`; files in the folder say only what differs. `extends: kelpie:<name>` resolves to the embedded text, never a file: `:` is not in an `AgentName`, so it never collides with a file, every build uses its own baselines and `--rollback` needs nothing extra. A bare name in `extends` names a file only, no fallback to a shipped agent (`kelpie:nope` names the shipped ones, a bare name with no file says it names no file). #1190, `crates/core/src/agents/mod.rs`
- Baseline from the binary, not `.defaults/`: runners reread files each wake, so one still on the old build during an upgrade would read a new baseline from disk, and a key it does not know stops it. #1190
- `body: append` in a file's frontmatter puts its body after the parent's, blank line between, at each step of a chain. No `body` key: a non-empty body replaces the parent's, an empty one takes it. Any other value, or the key twice, refused with its line; blanked in the merged text so later lines keep their number. #1190, `crates/core/src/agents/extends.rs`
- `add` writes each missing shipped agent as a stub, `---\nextends: kelpie:<name>\n---\n` (`qwen` only where its script exists), never over a file. #1190, `src/flock/add/mod.rs`
- `agents/.defaults/<name>.md`: every shipped agent whole, mode 444, first comment says kelpie writes it and to override in `agents/<name>.md`. For reading and diffing, nothing loads it (the loader reads only `.md` files directly in `agents/`). Written by `add` and by the dog's start, so each upgrade's restart refreshes it; replaced by rename of a temp file each writer creates new (pid and a number, the next free one), removed on failure, so a read never sees half and two refreshes never share one; a `.tmp` a minute old is a crash's and the refresh removes it; on Windows the target's read-only flag is cleared before the rename. #1190, `write_baselines`, `crates/dog/src/dog/mod.rs`
- No migration (the maintainer's install is the only one, fixed by hand), no hash tracking, no `doctor` line for a body that replaces its baseline's. #1190
- Baseline = a shipped file with `role` and a body, no binding keys (`harness` `model` `effort` `second_look` `usage` `url` `gateway` `context` `tools`); binding = those keys, in the operator's file. The ten baselines (defect-hunter standards spec security-reviewer issue-writer pm advisor researcher representative triager) still carry theirs in this slice, so no stub changes yet. `Agents::embedded()` holds whole agents only; `extends: kelpie:<name>` resolves in both lists. #1232, #1282
- Unbound = merged frontmatter has a `role` and no `harness`. The loader leaves it out of the book and keeps it in `Agents::unbound()` (name, path, role), so one stale stub stops no project that never names it. `find` and `Writer::of` refuse a name that is unbound, or a baseline's name with no file, with `shep kelpie agents new ...`; `doctor` gives one `missing` line per unbound file (`src/doctor/unbound.rs`). #1282
- `write_defaults` (so `add`) writes stubs for whole agents only; `.defaults/` still gets every file. #1282
- `agents new <role>` (`src/agent_verbs/mod.rs`) writes `extends: kelpie:<baseline>` + binding keys, or `role: implementer` + them (`--name` required, no baseline). Text is read by `baseline::check` (the loader's merge and parse) before any write, so a refused binding writes nothing; writes over no file but an unbound one. `agents list`: agents, unbound files, baselines with no file. #1282
