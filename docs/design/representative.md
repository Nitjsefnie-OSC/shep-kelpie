# Representative

The agent that words what kelpie says to a contributor, in one voice. Code decides what happens and drafts the facts. The representative only puts them into words. Slice 1 of #616. Nothing posts yet, and #627 and the slices after it wire posts through this call.

- Agent file `representative.md`, role `representative`, `Expert`-shaped frontmatter (harness, model, effort, `usage`, `lease`, `url`, `gateway`, `context`), so it runs on any harness as the advisor and researcher do. Shipped as Opus 5.5 at medium on Claude Code, written by `add`. `src/agents.rs`, `src/agents/front.rs`, #869
- `agents.representative` names it, default `representative`, unlike `advisor` and `researcher` which have none. `Settings::representative` checks it apart from `role_agents`, so `contributions.pick = "off"` needs no file. `src/settings/agents.rs`
- `Runner::open` checks it when `contributions.pick` is not `off`. A name with no file, or a file whose role is not `representative`, refuses to start naming `agents.representative`, as `security_reviewer` does. The built-in default stands in for a missing `representative.md`, so only a custom name can lack a file.
- The shipped body is a first draft that #616's wording test tunes (slice 3). It speaks as kelpie in the first person, openly a bot that works for the maintainer, never as the maintainer. Warm, humour rare and never in a no, a thanks-close, a second release ask, a frustrated reply or security. It leads with what the contributor does, never decides or promises a merge (a ruling decides), states only the facts given, writes English only (one line in the contributor's language allowed), at most one emoji and none in bad news, no sign-off. Its house rules: no em dashes, bold labels, "not X but Y", one-line closers or staged openers.
- One call per post: `Runner::represent(&Post)` in `src/runner/representative.rs`. A fresh session every time (never resumed), `Tools::Answer`, no read folders and no fence, so it reads and runs nothing. It runs in `<project>/representative/` and gets no repo plugins or MCP servers (`repo_setup` does not list it).
- The prompt holds the kind of post (a short instruction from the caller), the facts the caller drafted, the representative's earlier posts and the contributor's text. Earlier posts come as comment ids and are read again through the forge, so edits show. One that cannot be read is left out. Earlier posts and the contributor's text go through `src/runner/untrusted.rs` as data.
- The reply is checked in code before it is returned. Every `@login` (also `@org/team`, `@app[bot]`) that is not the contributor's goes in backticks so it pings nobody. Mentions already in an inline code span with a closing run, or in a fenced block that closes, are left alone, and a backtick or a fence that closes nothing protects nothing. An email's `@`, an escaped one and one in a web address are left alone. Nothing is refused for its content.
- A failed call or an empty reply is an error to the caller (`RepresentError`), and the caller's own failure rule applies. The pacer is the caller's too.
- Spend: a ledger line under role `representative`, kind `post`, with the pull request, and a `representative` total in `usage` apart from the work items. No work item records it (`src/work_item/tally.rs`, `spend.rs`), and no code graph reaches it.
- Harnesses: Claude Code, pi, Codex and goose all run it (`harness.representative` in `docs/parity.toml`). goose's `refuse_unsupported` allows a `Representative` `Answer` call, which with no fence runs in chat mode with no extension.
