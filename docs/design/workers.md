# Workers

Runner loop, worker turns, agents and harnesses. The fence is in fence.md. Skills and plugins are in skills.md.

## Runner and turns

- Loop never waits on an agent call: each runs on its own thread, one per item, beside the PM's (triggers and `status` answer meanwhile). #318, ADR 0005, `runner/flight.rs`
- `status`, `drain` and `undrain` answer from a copy the loop posts, not from the runner's lock, which a pass holds through its forge calls. A `drain` or `undrain` answered that way sets its flag at once and leaves the rest for the pass. One answered with the lock free takes up what the other left waiting, so the last ask is the one that stands whichever way each was answered, and a `drain pause` asked for once is asked for. A pass checks that it drains again after it prepared a turn, whose token mint and worktree ask the forge with the lock held. A review round checks again after it reads the issue it reviews the criteria from. No forge read sits between a step's check and the call it starts: `main`'s workflows are read before any work item is stepped, not after the pass chose its call. The loop posts again wherever a call becomes in flight, so `drain` never answers that nothing runs while one has. #916, `runner/posted.rs`
- A project's base branch is a value, `Git::base()` in `crates/core/src/settings/git.rs` (the `git.base` setting, `main` when absent; a change waits for the runner's next start), not a constant. Worktrees, the briefing, merge, adoption, contributions, the dev server and skill files read it from there. The guard is its own process, so it gets `--base=<branch>`, emitted only when not the default. #1047
- Harness files carry the issue (`settings-<issue>.json`); runner git waits 2s for a ref lock, 5s for `packed-refs`. `runner/turn.rs`
- On stop: SIGTERM each call's process group, save, exit inside shep's 1.6s `kill_timeout`; restart resumes each item from its session. A `handover` trigger instead keeps the calls running (agents.md). ADR 0005
- Worker owns one item, builds inline, no plan or crew; instructions and headless rules forbid sub-agents. ADR 0006
- Compaction is in compaction.md: `WORKER_COMPACT_PAST` (150k), `worker.compact_window` and the `COMPACT` call, on each harness. #760, #761, #770, #792
- Agents never see budget numbers (it makes models stop after each task). `runner/turn/budget.rs`
- Implementers default `sonnet-high`, `opus-high` for work hard to undo. #313
- `worker.turn_timeout` (60 min) counts from turn start, so restart buys no hour; past it parks `turn-timeout`, unless the worktree shows a commit the base lacks or a file written in the last 10 min: then the turn resumes with no ruling, up to 3 times per work item (`ceiling_resumes`; #1040); lease wait refunded. #16, `runner/turn/unfinished.rs`
- Failed turn parks `stuck` `turn-failed`. #57
- Pause ends a Claude Code or pi worker turn at its next tool result, not its end: runner writes `kelpie-pause` in the item's build folder (the one folder the guard can read); `kelpie guard --pause=<build>` as `PostToolUse` answers `{"continue":false}`, pi's guard extension calls `ctx.abort()`, each leaving `kelpie-paused`, which tells a paused turn from any other. No unpushed check, review or ruling, same stage, no slot or lease; next start resumes with a fresh ceiling. Else a Codex or goose call keeps the old pause. #821, `crates/core/src/guard/pause.rs`, `runner/turn/paused.rs`; its log lines are in log-lines.md
- `[builds]` `max_gb` (20) caps an item's build folder, `min_free_gb` (20) keeps disk free (0 = off). Folder and disk are read once a minute per item during a turn; past a limit the runner pauses and logs once. After the turn it prunes the cargo cache it did not touch (`incremental/`, `deps/`), then resumes with the pause prompt, or holds (`held_up`) while over. `status`: `build_bytes`, `disk_free_bytes`. #857, `runner/builds.rs`
- A due turn that does not start says why in `status` (`held_up`) and on the board line: no slot, push by someone else, pacer hold, token wait, drain, `attach`. Memory only; one log line once held 5 min. #503, `runner/turn/held_up.rs`
- First turn ending with no PR or question resumed once, then parks; uncommitted work with no push sent back once to commit. #140, #275
- Item whose issue closed with no work ends with no ruling; a parked item's issue is read every 5 min. #385
- Retro moved from worker to PM: batch after every 10 finished items and at a drain, one call with the PM's agent over a digest (`journal.jsonl`, rulings, ledger). Worker keeps a PR-body `Friction` section. Off unless `skills.retro`; no slot, never retried, saved unread (agents acting on retros loop). Digest counts conflicts per file, rounds, late findings, known flakes (also in CI fix prompts). #361, #566, #657, `runner/retro.rs`
- Worker asks with a `<kelpie-question>` block ending its message; parks on a `question` ruling with optional `- ` choices. #13
- Instructions tell a worker with commits made to push and have its draft open before it ends on a question (`OPEN_YOURSELF`, `HAND_OVER`), so the ruling is posted on the pull request: turn-end discovery runs for a question turn too, opening a hand-over worker's draft from its file, and the saved resume is `ReviewFirst`. With nothing pushed it is posted on the issue, or kept on a local ticket. #1037, `crates/core/src/profile.rs`, `runner/turn/ended.rs`
- A choice only the maintainer can carry out (run a command, change a setting, grant a permission) starts with `You`, names what they do and what the worker does after, in the worker's instructions and the PM's `candidates` and `escalate`: an answer is the worker's next turn, so a bare verb reads as an order to a worker that may be unable to obey (shep#829). Neither prompt offers more worker GitHub access as a choice; the token's scope is a design decision (`docs/design/github-app.md`). #805, `crates/core/src/worker-instructions.md`, `runner/pm/prompt.rs`
- A worker whose item depends on an external API it cannot read the docs of asks in a `<kelpie-question>` block before it guesses, offering the issue's docs pasted in or the host in `worker.allowed_domains`. `tools` on a Claude Code agent file adds `WebFetch`, bounded by those domains. #997, `crates/core/src/worker-instructions.md`
- `shep kelpie attach <issue>` hands a worker's Claude Code, pi, Codex or goose session to maintainer, sandboxed (goose: `goose session --resume --name <id>`, `GOOSE_MODE=approve`, so it asks before each tool call and the hook still refuses what a worker may not do); held by pid + start time. #325, #766, #775, #796
- PR template filled, ending `Resolves #<issue>`; no repo template means the owner's `.github` one, read at start and reread, cut past 8 KiB, and written to `pull-request-template.md` in the item's build folder on every worker call, which the worker reads when it writes its body: the instructions only name that file, since Claude Code carries them on every request and the template is used once (#992). `worker.instructions_file` adds project rules. #596; #87, `runner/instructions.rs`
- Out-of-scope finds named in final message; deferred review findings in the deferred findings file, whose path, with the disputed findings rules and the design-choice rule, is in the header of the findings file a fix turn reads rather than in the instructions (#992); PR stays on its issue. #649, `runner/follow_up.rs`

## Not built

- Claude Code through a gateway: needs per-harness forwarding + a pacing decision. Gateways go through a port (`crates/core/src/ports/gateway.rs`) with paddock and `openai` adapters; `openai` holds no lease and may evict a turn's model. #352
- Usage calculator handing workers decisions, never cost figures. `docs/design-log.md` Decided, not built
- Shots on the pull request: in git history. ADR 0006, #54, #131. The preview's other half, a live look at the UI, is built as the browser (browser.md). ADR 0011
