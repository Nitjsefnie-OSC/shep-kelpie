# Board

The board, work items and adoption. Projects and slots are in `work.md`.

- Tracker: GitHub Issues + `ready-for-agent`; board of work items lives in kelpie (maintainer triages where they already work). `core/board/`
- A ticket's id is a `TicketId`: a GitHub issue number, or `k12` for a local ticket (ADR 0014). Board, dispatch, briefing, `Tickets` and the state file name tickets: work items, rulings, finished, dropped and saved order are keyed by the id, a ruling answered by its pull request's number or its ticket's id before there is one, and older files load their numbers as GitHub ids. Triage, adoption and contributions keep issue numbers, being GitHub's own listings. An `AgentCall`'s `issue` is an `Option<TicketId>`; a hook payload's is a GitHub number or `"k12"`. #1005, #1010, `crates/core/src/ticket.rs`, `core/board/`, `runner/dispatch/`, `crates/core/src/state/mod.rs`
- Issue writer: `role: issue-writer`, Claude Code only, Opus 5.5 at medium. Splits each request into the smallest pieces that ship alone, labels `agent:<name>` and priority; each piece has `Touches:` (every file its changed names reach; past 13, split by module), named tests, status label after its links, never mentions cost. No planning call (plans no better, shared plans spread bugs). Claude Code starts it on `--tools Bash,Read,Glob,Grep,Skill` (its commands are its guard's, `Skill` for what the repo's plugins carry) and no `--strict-mcp-config`, so the servers it loads still load; `ISSUES_DENY` stays as the second fence. #985, `docs/facts/headless-claude-code.md`. ADR 0006, #324, `agents/issue-writer.md`
- `shep kelpie issue "<request>"`: headless, fresh `origin/main`, files `ready-for-human`; fails on issue missing criteria or labels, notes `touches <n> files`; no lamb, unpaced. `src/issues/mod.rs`
- `--interactive`: `claude` with no `allow` rule (maintainer approves each command issue text could steer), files `ready-for-agent`. Previews each issue's `agent:` label and asks to apply them, none or some; no label = default implementer, so its guard allows zero or one. No `--tools` either: that session writes `GLOSSARY.md` and `docs/adr`, and the maintainer's own settings stay in force beside it. `src/issues/mod.rs`, `src/issues/prompt.rs`
- Issue-writer guard: allow-list of `gh issue` reads, creates, label/link edits on issues it filed; no shell syntax, no git (git options too wide for deny-list). `crates/core/src/guard/issues/mod.rs`
- PostToolUse ledger records filed issues so edits/links reach only those; fails closed; hook seeing `tool_response.stdout` unchecked.
- Design settled first: interactive runs vendored `grill-with-docs`, headless writes `## Open questions` with recommended answers; facts from repo, never maintainer. #365
- Interactive docs land on `kelpie/docs-<id>` worktree, writes confined to `GLOSSARY.md` + `docs/adr`, then draft PR with no `Resolves` (checkout untouched, no runner takes it). #365
- Unlabelled ready issue + several implementers: runner makes pick-only issue-writer call and labels it itself; failure raises `stuck` `unlabelled`. #381, `runner/flight/label/`
- Board order: `priority: P0` to `P4`, then unlabelled, oldest first; adoptions and reworks ahead; blocked or skipped issue never holds up next. Keeps an `order`: new or re-prioritised issue goes after last of its priority; `board` lists ready issues numbered, `board move <issue> <position>` and `board top <issue>` reorder them; a non-ready issue or position past the end is refused. #144, #494, #495, `core/board/`
- Adopt: `adoptable` refuses a branch a worktree kelpie did not make holds (`git worktree list --porcelain`), so `adopt` queues nothing that cannot start. A queued PR whose pass fails with `AdoptError::Worktree` raises one `stuck` `adopt-failed` ruling (id is the PR number), raised again only when the error changes (an answered one included, until a restart), a failure to list the worktrees raises none, cleared when a pass adopts it or it leaves the queue. While any queued PR fails, `status` lists it under `skipped` (`reason: adopt`) with `error` and `since` (in memory, reset on restart). #713, `runner/adopt/`
- `agent:<name>` label picks implementer, `!` pins against fallback; unknown or doubled label skipped; kelpie only adds missing `agent:` labels (deleting strips every issue). #381
- Issue with sub-issues never worked (they are, instead); closed when all sub-issues closed. The sweep also closes an open issue off the ready list once its sub-issues are all closed with one completed (all not planned stays open); a sub-issue still open on the board's reread stops the close, and one with none completed is read again when its count changes or an hour on. #738, `runner/parent.rs`
- Held issue carries `in-progress` (courtesy, refusal logged). #199
- Merged issues never retaken until they read closed (`Resolves` lags merge); `drop` keeps the PR, lists issue `dropped` until it leaves the ready list; its recheck leaves the lock. Any item ended with no merged pull request (`drop`, a `no` on a turn-timeout, turn-failed, push-refused or agent-files ruling, a yes on `closed`) lists `dropped`, not `finished`, and `dropped_text` keeps a digest of the issue's title and body from the board's first read after: an edit returns the issue, as does the label put back. An edit made before that first read is not seen (`shep kelpie add`). #172, #481, #1205, #1229
- Kelpie works its own repo from a separate clone, never the session checkout; worker rules in `CLAUDE.md`; merged changes reach runner only on upgrade. #140
