# Metrics from transcripts

What a call's transcript says once it ends, as series, and the reports that read transcripts. The rest of kelpie's numbers are in `metrics.md`. ADR 0012, #920, #924, #968.

## Series

MCP servers, read from a call's transcript once it ends: the agents a call runs on are wrapped (`runner/transcript_count/`), which find the session's file through `Agents::transcript` and parse it (`crates/facts/src/mcp_use/mod.rs`). A call that wrote nothing to it counts nothing.

- `kelpie_mcp_servers_total{server,outcome}`: each server in the call's reach, `connected` or `failed`. Claude Code writes how its servers stand only when that changes, so the transcript's last such line is how they stood, and with none, a server whose tools the last prompt snapshot lists connected; `needsAuth` is `failed`, `pending` is not counted. pi names no server that failed: it writes the tools its session adds and removes and the calls it answers, and kelpie reads the last word the file says of each server, so one whose tools the session leaves available as it ends, or whose tool call it answered with no error, is `connected` and one with neither `failed`. A failed server is a standing warning naming the call and why, Claude Code's error code or that the server's tools were not in the session as the call ended, ended when a later call finds it connected (`docs/facts/mcp-servers.md`).
- `kelpie_mcp_tool_calls_total{server}`: the call's own `mcp__<server>__<tool>` calls, from where its file stood when it began; each server it was given is sent, at 0 if never called. Claude Code and pi.

Requests, read from the same file by the same wrapper (`crates/facts/src/request_use/mod.rs`, `docs/facts/transcript-requests.md`), for the requests the call itself made, of the worker, the reviewer and the project manager, the long sessions (the one-shot roles' would hold seven series for each harness more than the cap of 240 has room for). Claude Code, pi and Codex (`harness.request-usage`):

- `kelpie_request_context_tokens{role,harness,le}`: requests by context size (input, cache read and cache write), as cumulative counters with `le` 150000, 200000 and `+Inf`: the worker's compaction threshold (150000) and the context window (200000). A 50000 bucket went with #1202, since the lock's three series did not fit the cap beside it, and it can return if the dog's 256 a sender rises (shep-pm/shep#733). More buckets did not fit the runner's series beside the plan, compaction and feature series, which `histogram_quantile` reads over a `rate`. The channel has no histogram type, so this counter has no `_total`. All three are sent with a role and harness's first request.
- `kelpie_cache_write_tokens_total{role,harness,after}`: tokens written to the cache, `after` `start` (the session's first request), `gap` (longer since the request before, which may be an earlier call's, than the cache keeps a write: 1 hour once a request has written to the 1-hour cache, else 5 minutes) or `growth`. All three are sent with the first. A role and harness holds 7 series between the two.
- A request is one however many lines Claude Code wrote it as; a reply that sent nothing is none.
- A worker's turn carried through a handover is counted by the image that adopts it. `CarriedTurn` holds a `Mark` (the transcript's folder, the folder of Codex's thread records, the session, its length and the time as the turn began), and the image counts the requests and the failed tool calls past it when the turn ends, with the note naming a hook that is not kelpie's, which it writes for the turn's issue. Its MCP servers are not counted, since the mark holds no servers.

Tool calls that failed, read from the same file by the same wrapper (`crates/facts/src/tool_error/mod.rs`, `docs/facts/tool-errors.md`), of the worker, the reviewer and the project manager, as their requests are. Claude Code and pi (`harness.tool-errors`):

- `kelpie_tool_errors_total{role,kind}`: each tool call whose result the harness wrote as a failure, by what made it fail. Thirteen kinds for each of the three roles is 39 series, which is why `SERIES_CAP` went from 200 to 240 (`metrics.md`). A result counts once, however many lines of output it holds: one failed command printed 621 `Operation not permitted` lines over 15 results. `kind` is the first that matches, so a guard refusal that also holds a sandbox error is a guard refusal: `guard-block` (kelpie's `guard` or `confine` refused it), `hook-block` (a hook that is not kelpie's refused it), `tool-not-given`, `unknown-skill`, `permission-refused`, `git-ref-lock`, `tmp-refused`, `path-refused`, `command-not-found`, `edit-miss`, `timeout`, `mcp` (a failed `mcp__*` call that says nothing else), `other` (a command that ran and failed). No tool, path or command is in a label: a hook that is not kelpie's is named in a note instead (`log-lines.md`). A refusal is kelpie's own when Claude Code's hook command is kelpie's binary with its `guard` or `confine` program next, and on pi when the extension's mark stands on a content block of its own. Each kind's phrase is read at the head of a line, where a line's own message is what follows the `<token>:` markers a program or a shell writes before it, so output that quotes an error is not that error (`facts/tool-errors.md`). Codex's rollout is read for its requests alone, and its MCP and tool calls wait on an untrimmed recording (#1279). goose reads no transcript yet (#784).

## Reports from transcripts

- `shep kelpie usage <project> --item|--context|--reads` (`--json` too; `--item` takes a ticket id, `340` or `k12`, and a ledger line's `issue` is one) join the ledger to transcripts by its `session` field, with no shepherd. A transcript is found through the `session-started` steps in `steps.jsonl`, never a guessed folder. Requests are read for Claude Code (one per `message.id`, subagent lines left out), pi and Codex (one per `token_usage_record`). `--reads` shows no touches for Codex, whose rollout names no file a tool call read (`harness.usage-reads`). `crates/core/src/usage/session.rs`, `crates/core/src/usage/requests.rs`, #926
