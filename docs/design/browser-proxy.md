# Browser proxy

The proxy every browser request goes through, outside any sandbox. Part of the Browser area: `docs/design/browser.md`.

- Every request the browser makes goes through a proxy kelpie runs for it, outside any sandbox, on a loopback port kelpie picks (`crates/adapters/src/adapters/bridge/proxy/mod.rs`, opened and dropped with the `Bridge`). The resolver rules name hosts and cannot hold a host to a port, so once the browser may open `localhost`, page code the worker wrote could reach every local service from outside the sandbox. `docs/facts/the-second-harness.md` measured the same reach for `allowLocalBinding`. On Windows the widening is the install's: the fence holds one loopback mode for the whole machine, so an `--allow-loopback` install gives `allowLocalBinding` to every worker, not only the dev server's (#1217, `docs/design/fence.md`).
- Chromium launches with `--proxy-server=http://127.0.0.1:<port>` and `--proxy-bypass-list=<-loopback>`, so loopback goes through the proxy too. The `Bridge` writes the config (`config.json` in the call's browser folder) that carries them with the resolver rules, which `EXCLUDE 127.0.0.1` so the browser can reach the proxy. From Chromium's documentation, not yet measured here.
- The proxy allows a `CONNECT` tunnel, or an absolute `http` URL, only to an `Origins` entry: each `browser.domains` host (`*.` and a parent included) on ports 80 and 443. The dev server's one port is added as `localhost` and `127.0.0.1`, dialed straight on the loopback (either address) with no lookup. Every other local address stays refused, and an IPv6 literal is not read as a host. Anything else gets a 403 and no connection is made.
- A listed host that resolves to an address that is not globally routable is refused: loopback, private, link-local, shared (100.64.0.0/10), benchmarking (198.18.0.0/15), documentation, multicast and reserved IPv4 ranges, and all IPv6 outside global unicast (2000::/3) less its special-purpose blocks, which takes in NAT64 and 6to4. An IPv4-mapped IPv6 address is read as its IPv4. One such address among several refuses the host. The address that was checked is the one dialed, so a second lookup cannot answer differently.
- A request is read as the forwarder reads one (`crates/adapters/src/adapters/forwarder/http.rs`): the head is capped at 64 KiB, a body at 64 MiB, the whole request must arrive in 30 seconds, and 64 connections are served at once, the rest getting a 503. A relayed request is sent on in its own form with `Connection: close`, the `Host` of its URL, and the proxy-hop headers dropped. A tunnel has no idle limit and ends with the bridge.
- A refusal is one log line on the runner's stderr, `browser proxy refused <host>:<port>: <why>`, never the path or query.
- The resolver rules stay as a second layer.
