# Agents

Agent files, harnesses, gateways and spend by role. The runner loop and fence are in workers.md, skills in skills.md.

- Agent = `<name>.md`, YAML frontmatter tagged `role` + Markdown body; bad file stops runner naming file + line. serde-saphyr (serde_yaml archived). ADR 0006, #313
- Embedded from `agents/`; home file overrides, `add` writes missing, reread each wake (edits land live). Item keeps its agent, runs the file as it is now. #313
- `extends` merges frontmatter keys as text before parsing (every check applies); parameters on a reference refused (each a new label + ledger key). #386, `src/agents/extends.rs`
- `agents.implementers` (default `["sonnet-high"]`, first is default), `reviewers`, `pm`, `issue_writer`; missing or wrong-role file stops runner. `src/settings/agents.rs`
- One agent interface for every role, harness details in adapters; harness that can't fence can't be worker. ADR 0006
- Harness parity: pi gets every capability Claude Code has, in the same PR or an open issue; Codex follows pi, blocked by its issue (maintainer, 2026-10-13: pi is in everyday use, Codex is not). A refusing default is a tracked gap. #752, #753, `CODING_STANDARDS.md`
- Every agent call (Claude Code, pi, Codex) writes stdout and stderr to files beside its settings, not pipes: a pipe the sandbox's Node made non-blocking killed Codex on large output, and files outlive the runner's memory. A record (`<settings>.call.json`: pid, process group, role, issue, output paths, `Ending` asked, the runner's `Flying` ceiling and turn flags) sits beside them from spawn to the call's end by any means, a stop included. A handover reads it. `src/adapters/process/record.rs`, #716
- A `handover` trigger replaces the runner's image with the installed build via `shep_handover`, keeping pid, children and shepherd channel, so shep sees no stop. The loop acts at its quiet point (between passes, no `git`/`gh`/merge child), and a call whose stdin is still being fed (`adapters::feeding`) or a notice hook running or queued on its own thread (`Runner::notices_running`) or a reply a forwarder is relaying (cut by the exec) holds it. Only worker turns this image started cross (Claude Code, pi and Codex), each as `Adopted` (pid, record path, `harness`, for pi `Kept`, for Codex the `session` id that names its thread record; `FORMAT` is 3, since an image reading 2 would not know a Codex turn's session) plus its ledger line in `Carry`; a PM, labelling, panel, retro, reviewer or already-adopted flight refuses it, and so does a live pi `attach`. Before the exec `Processes::seal` stops reaping, so a call ending then is read by the new image, and refuses while one is being read. The new image waits on each pid with `wait_for_child` and finishes the turn as the old would: output, cost, usage line. The probe checks the target reads `Carry`'s `FORMAT`; the `Fitness` gate starts the target once with `KELPIE_HANDOVER_CHECK` set, as a runner that stops after reading its settings (`starts`), so a build that fails there is refused with the old image running, and then refuses a feed or relay that began meanwhile. A build that still fails after the exec ends the carried calls' groups before the runner exits (`end_groups`), so none is orphaned, and shep restarts it. Any refusal leaves the old image running; the trigger's answer names why, or says `waiting` after 2.5s and the log has a later refusal. Fd 3 needs no carrying: the shepherd passes it without close-on-exec and `SHEP_CHANNEL_FD` stays set. A pi turn's `Kept` has its forwarder socket, model server and lease id, never the key: the new image reopens the forwarder at that path (`Forwarder::reopen`) with its own gateway settings, and `ModelGateway::resume` renews the lease at once and releases it when the call ends, so no second take, eviction or early release; a chat request in the gap before the reopen is refused. Adopted turns have no idle watch, unreachable retry or login refresh. A Codex turn holds no lease and has no forwarder, so it carries nothing else and the new image finishes it as `run` does (thread record, usage). `src/adapters/pi/adopt.rs`, `src/adapters/codex/adopt.rs`, `src/sheep/handover.rs`, `src/runner/flight/carry.rs`, `src/adapters/process/adopt.rs`, #717, #752, #753
- `shep kelpie upgrade` hands each online runner over before it drains or restarts it, and waits for its `status` `build` (stamp of the file it started from, `upgrade::seen`) to match the installed file. A refusal, a build from before `handover` or no new build in `patience.start` (after a `withdraw_handover`) drains and restarts it as before, saying why. The dog is restarted plainly; `--now` skips the handover. `src/upgrade/handover.rs`, #718
- pi: second harness; kelpie extension runs `confine` + `guard`; forwarder passes only chat completions. No Claude Code hooks, so `worker.guard_hooks` naming pi or Codex stops at load. #130, #235, `src/settings/agents.rs`
- Codex: third harness (ChatGPT plan windows beside Claude's, each paced on own); session ids map to Codex threads. Own login in `codex_home`, fresh `CODEX_HOME` per call (`~/.codex` copied maintainer's history). #233, `src/adapters/codex.rs`
- goose: fourth harness, a model on an OpenAI-compatible server, researcher only; #788 opens the implementer, #789 the reviewer and advisor. Its adapter runs one `goose run` per call in the sandbox and takes the researcher only (`docs/facts/goose-as-an-agent.md`). #784, `src/adapters/goose.rs`
- Codex writes only an allow-list of its home (`.env`, `AGENTS.override.md` could disable guards); only Codex workers get a shell (reviewed PR could steer it). `src/adapters/codex.rs`
- `e2e.host` ssh alias, must be disposable (workers edit the script); worker asks only `take: "e2e"`; dog runs one per host under 30 min. #415, #521, `src/dog/e2e.rs`
- Local implementer (`usage: none`) can be default; without a gateway keep `active_items` 1. #381
- Turn awaiting its model marked `waiting` in memory; with `agents.fallback_after`, waiting first turn moves to next free implementer; later or pinned turns never (lose session). A turn's last output is read from the call's stdout file for pi (`src/adapters/pi/activity.rs`: none until a model event, a `message_update`, `tool_execution_*`, `compaction_*`, `auto_retry_*` or an assistant `message_end` with content, so the opening lines pi writes at once do not count; a file past 1 MiB counts unread; a last line without its newline is not read) and Codex, not pi's session file, which moves once per message. #381, #768, `src/runner/flight/waiting.rs`
- Unreachable pi host retried 30s to 5 min for 30 min before parking. #457, `src/runner/turn/unreachable.rs`
- `usage` (`claude`, `codex`, `none`) must match harness; `none` never paced; a gateway queues its calls, a `url` model is unqueued. #129, #502
- Gateway (`kind`, `url`, `key_env`) is reached through the `ModelGateway` port (`src/ports/gateway.rs`: models, key check, optional lease), one adapter per `kind`, `paddock` (the default) and `openai` (any OpenAI-compatible gateway: models and key from `GET /v1/models`, no lease, so it may evict a model a turn runs on); a kind with no lease runs its turn at once, ceiling from its start. It queues and places models: agents unpaced, lockless; key unset in every call + child; every call (worker turn, reviewer session or round) holds a heartbeat lease, and a `turn` reason is the wait (`gpu_wait`, `waiting`); a lease paddock refuses to renew, or leaves unanswered past its ttl, fails the turn, and a drop releases at once; every chat call to a keyed gateway sends `x-paddock-priority: batch` (paddock serves no priority as interactive, kelpie runs unattended); a worker's pi chat calls and an endpoint round's also send `x-paddock-lease: <id>`, their own lease (a reviewer's session names none), and a round sends `x-paddock-max-wait: 1800` too, taken before its forwarder opens (without it paddock gives a request any kelpie lease's free turn, and the first-come order is lost). #352, #497, #500, #606, #607, #712, `src/spawn.rs`
- Spend = tokens per role, dollars only where reported; unpriced calls counted (zero never reads as free). #129
