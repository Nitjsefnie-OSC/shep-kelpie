# Contribution push

How kelpie pushes a fork worker's commits to the contributor's branch. Settings and detection are in `contributions.md`, the adoption of a released pull request in `contribution-release.md`. #633

## Push to the fork

- A worker whose work item's `remote` is a `Fork` only commits. `WorkerProfile.kelpie_pushes` adds `git push` and `git push *` to its denied commands and a bullet to its instructions saying a commit is enough, and the guard hook carries `--kelpie-pushes`, which makes `git push` refuse with the same words (`crates/core/src/guard/git/mod.rs`). Every adapter emits the flag (claude, codex, goose, pi). Prompts that say "push" are left, since the instructions say every push means a commit. #633
- `Runner::push_to_fork` (`runner/contributions/push.rs`) pushes the worktree's head to the fork's branch with `worktree::push_commits` (`crates/process/src/worktree/push.rs`): by commit, `<sha>:refs/heads/<theirs>`, no `+` and no `--force`, run in the repo outside the sandbox, so the maintainer's login is the one git there holds and no credential reaches the worker's env or files. It runs after each Ok turn (`end_turn`), at the top of `check_ci` and before a review round (`before_round`).
- The refusal of the worker's own push is a guardrail, as for any worker: a copy of `git` under another name is not matched, and the worker's token (App, one repo) can push to an editable fork (#1134). A token without write for a fork work item is not built.
- It pushes only while the fork's head is the one the work item knew (`known.head`). A different head is a contributor push: nothing is pushed, the gate reads the fork's head and raises the foreign-change ruling, and the commits wait in the worktree. A turn whose push is held is not sent back for a push it cannot make.
- A fork that refuses the push (edits turned off since, the branch deleted, or a branch the commit does not extend), or cannot be reached, raises `stuck` `push-refused { why }` with git's words. The public comment says only that the fork refused. A yes pushes the kept commits again at the gate; a no stops the work item. State version 77.
- Measured by #1134 (`docs/facts/pushing-to-a-contributors-branch.md`): the App's token and the maintainer's login both push to the branch while "Allow edits" is on, and neither once it is off. The push uses the maintainer's login because only it can approve a pending run.
