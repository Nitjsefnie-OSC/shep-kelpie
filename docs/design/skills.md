# Skills

The skill each step runs, the plugins the repo turns on, and how each harness loads them.

- Every step runs a skill: mattpocock/skills vendored + pinned in `skills/`, kelpie prompts as fallback; `[skills]` overrides a step. #147, `src/skills.rs`
- Skills byte-identical; kelpie headless rules win (decide and record, no sub-agents, kelpie reply format, no own `/code-review`). Skill that can't load runs kelpie prompt, logged (unknown slash command passes as text). #170, #147
- Plugins enabled in `.claude/settings.json` on `origin/main` reach every Claude Code agent (skills, agents, commands, hooks, MCP), and a pi or Codex agent's skills and MCP servers (a Codex server as a `-c mcp_servers.<name>` override, one it cannot load dropped with a note, `src/adapters/codex/mcp.rs`), never from a worker branch. Sources: plain git transports, no `-` or `::` addresses, no links or `..` (default branch settings aren't maintainer's alone). #569, #570
- The repo's own `.claude/skills`, `agents`, `commands` and the `hooks` of `.claude/settings.json`, read from `origin/main`, are one more plugin, `kelpie-repo`, for every call; a Claude Code call in a worktree whose agent files equal `main`'s (`fence::matches_main`) loads them there and skips it. `repo_setup.own = false` leaves it out. #591, `src/skills/repo/own.rs`
- A pi call loads the `skills/` folder of every plugin it is given, the step skill's own folder first so its name wins a collision, after `--no-skills` (nothing of `~/.pi`, `~/.agents` or the worktree loads) and with `--no-approve`. A pi worktree's `.claude` is never read, so the `kelpie-repo` plugin reaches a pi call even in a worktree that matches `main`. A call with no tools gets only its step skill; every other keeps `read`, the way to a skill that names another. Plugin commands, agents and hooks do not reach pi. #763, `src/adapters/skills.rs`
- A Codex `Tools::Work` call gets every skill folder of every plugin it is given linked into `<call's CODEX_HOME>/skills/<name>` by `prepare`, the first plugin winning a name and the last call's links removed. The call cannot write that folder, so it cannot plant a skill; `~/.agents` stays unread, and `plugins` and `skill_mcp_dependency_install` stay off. A call with no shell cannot open a `SKILL.md`, so it keeps its step skill pasted into the prompt and gets no links. Not measured live (`docs/facts/codex-as-an-agent.md`). #772, `src/adapters/codex/skills.rs`
- A plugin's MCP servers and `.mcp.json` on `origin/main` join the call's `--mcp-config` and `permissions.allow` per `parts` and `roles`; not `Retro` calls. #573, `src/adapters/claude/mcp.rs`
- `[app.dogs.kelpie.repo_setup]` narrows them: `plugins = false` drops the repo's, `roles` picks the calls that get any, `skip` drops `name@marketplace` ids, `parts` picks which of a plugin's parts load (a plugin's hooks stay in its own `hooks/hooks.json`, so they cannot replace kelpie's), `extra` adds ids with a one-string source (`github:o/n#ref`, `git:url`, `directory:dir`) that lookout can edit. The CLI's headless issue writer isn't the runner, so it loads them itself into a per-run folder. #571
