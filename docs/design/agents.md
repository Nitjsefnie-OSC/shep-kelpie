# Agents

Agent files, harnesses and gateways. The runner loop and fence are in workers.md, skills in skills.md, waits and spend by role in waits-and-spend.md.

- Agent = `<name>.md`, YAML frontmatter tagged `role` + Markdown body; bad file stops runner naming file + line. serde-saphyr (serde_yaml archived). ADR 0006, #313
- Embedded from `agents/`; home file overrides, `add` writes missing, reread each wake (edits land live). Item keeps its agent, runs the file as it is now. #313
- `extends` merges frontmatter keys as text before parsing (every check applies); parameters on a reference refused (each a new label + ledger key). #386, `src/agents/extends.rs`
- `agents.implementers` (default `["sonnet-high"]`, first is default), `reviewers`, `pm`, `issue_writer`; missing or wrong-role file stops runner. `src/settings/agents.rs`
- One agent interface for every role, harness details in adapters; harness that can't fence can't be worker. ADR 0006
- Harness parity: pi gets every capability Claude Code has, in the same PR or an open issue; Codex follows pi, blocked by its issue (maintainer, 2026-10-13: pi is in everyday use, Codex is not). A refusing default is a tracked gap. #752, #753, `CODING_STANDARDS.md`
- Every agent call (Claude Code, pi, Codex, goose) writes stdout and stderr to files beside its settings, not pipes: a pipe the sandbox's Node made non-blocking killed Codex on large output, and files outlive the runner's memory. A record (`<settings>.call.json`: pid, process group, role, issue, output paths, `Ending` asked, the runner's `Flying` ceiling and turn flags) sits beside them from spawn to the call's end by any means, a stop included. A handover reads it. `src/adapters/process/record.rs`, #716
- pi: second harness; kelpie extension runs `confine` + `guard`; forwarder passes only chat completions. No Claude Code hooks, so `worker.guard_hooks` naming pi or Codex stops at load. #130, #235, `src/settings/agents.rs`
- Codex: third harness (ChatGPT plan windows beside Claude's, each paced on own); session ids map to Codex threads. Own login in `codex_home`, fresh `CODEX_HOME` per call (`~/.codex` copied maintainer's history). #233, `src/adapters/codex.rs`
- goose: fourth harness, a model on an OpenAI-compatible server; worker (in the fence, by a `PreToolUse` plugin), researcher (no tool), reviewer, advisor and retro (same plugin, `guard --goose=<build> --read-only`: `shell` runs only the Codex read-only list, `tree` allowed, `write`, `edit` and any other tool refused as a call that writes no file; retro and advisor lose the sandbox's `write`; a call with no fence has no extension and `GOOSE_MODE=chat`; a resumed reader takes no extension flags, so the hook is its only gate). A goose reviewer gets a fence with an empty folder of its own, as Codex's does. #789. goose cannot run an `after_command` hook: its `PostToolUse` has no result. A worker turn crosses a handover (handover.md). `docs/facts/goose-as-an-agent.md`. #784, #788, #791, `src/adapters/goose.rs`
- goose's watch (`shep kelpie watch`) reads the call's stdout file, since its sessions are in SQLite under `GOOSE_PATH_ROOT`: `GooseCli::transcript` logs the call's goose root as the `session-started` step's folder (the log's shape is unchanged), and the locator reads the root's sibling `<stem>.stdout.jsonl`. The file is emptied by each call, so `transcripts::format_of(Harness::Goose)` is `None` and the researcher's panel (`src/runner/panel/folders.rs`) gets no worker-session text from goose: no file holds a whole session. An `error` event has no time, so the watch gives it the time of the line before it. #790, `src/watch/goose.rs`, `src/watch/locate.rs`
- Codex writes only an allow-list of its home (`.env`, `AGENTS.override.md` could disable guards). Shell: worker `guard`, others `guard --read-only`, none unfenced. `src/guard/reading.rs`
- `e2e.host` ssh alias, must be disposable (workers edit the script); worker asks only `take: "e2e"`; dog runs one per host under 30 min. #415, #521, `src/dog/e2e.rs`
- Gateway (`kind`, `url`, `key_env`) is reached through the `ModelGateway` port (`src/ports/gateway.rs`: models, key check, optional lease), one adapter per `kind`, `paddock` (the default) and `openai` (any OpenAI-compatible gateway: models and key from `GET /v1/models`, no lease, so it may evict a model a turn runs on); a kind with no lease runs its turn at once, ceiling from its start. It queues and places models: agents unpaced, lockless; key unset in every call + child; every call (worker turn, reviewer session or round) holds a heartbeat lease, and a `turn` reason is the wait (`gpu_wait`, `waiting`); a lease paddock refuses to renew, or leaves unanswered past its ttl, fails the turn, and a drop releases at once; every chat call to a keyed gateway sends `x-paddock-priority: batch` (paddock serves no priority as interactive, kelpie runs unattended); a worker's pi chat calls and an endpoint round's also send `x-paddock-lease: <id>`, their own lease (a reviewer's session names none), and a round sends `x-paddock-max-wait: 1800` too, taken before its forwarder opens (without it paddock gives a request any kelpie lease's free turn, and the first-come order is lost). #352, #497, #500, #606, #607, #712, `src/spawn.rs`
