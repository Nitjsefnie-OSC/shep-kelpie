# Skills

The skill each step runs, what a worker gets of the vendored ones, the skill that words its pull request body, and the issue skill. The plugins a project turns on are in plugins.md.

- Every step runs a skill: mattpocock/skills vendored + pinned in `skills/`, kelpie prompts as fallback; `[skills]` overrides a step. A worker's copy holds only the skills its steps run and what those call, from `vendored::CALLS` (closed transitively): a step left out seeds its default only for the worker's four, a step the project names `kelpie` seeds its own (how a named `retro` gets its skill and `writing-for-agents`), and `none`, a `path` and a `plugin` seed nothing, so `triage`, `spec` and `reset` run kelpie's own prompt and name no skill in `status` until the project names one (seeding `triage` would also write the `grilling` and `domain-modeling` it calls, which a harness lists). The cut is what a harness lists: Claude Code names every skill a plugin holds on every request. `write_vendored`, which the interactive issue writer uses, still writes all of them. #147, #993, `crates/core/src/skills/mod.rs`, `crates/core/src/skills/vendored.rs`
- Skills byte-identical; kelpie headless rules win (decide and record, no sub-agents, kelpie reply format, no own `/code-review`). Skill that can't load runs kelpie prompt, logged (unknown slash command passes as text). #170, #147
- A worker's turn carries the headless rules once, in its instructions, so the `implement` and `ci_fix` prompts carry only the slash command and kelpie's reply format beside them; a worker with no `tests`, `pr` or wording skill has nothing in its instructions, and its prompt keeps the block. Retro, triage, spec and reset are calls of their own, and keep it. #992, `crates/core/src/skills/mod.rs`
- The worker writes its own pull request body, with kelpie's `wording` skill beside the `pr` skill: `mix-v2` of `docs/specs/wording-results.md` cut to "Lead with what they need", "Keep it short" and "Patterns that read as a bot" (the contributor-facing "Sound like a person", "Thanks and praise" and "Humour" dropped), with its `humanizer` and `i-have-adhd` MIT notices, in `skills/kelpie/wording/` beside the vendored copy, which stays byte-identical. It is written to `kelpie-wording` beside `mattpocock` and reaches a call as any plugin does (Claude Code `--plugin-dir`, pi `--skill`, Codex and goose by their linked skill folders, plugins.md). The instructions name it, `/kelpie-wording:wording`, only where they tell the worker to write `pull-request.md`, so it loads when the body is written; a body the worker opens itself is not worded by it. `[skills] pr = none` turns it off with the `pr` skill, and a `pr` replacement keeps it; `[skills]` has no key for a skill outside a step, so it has no switch of its own. Why a skill in the worker and not a representative call: loading it when the body is first written adds 142k units ($0.24) over 10 merged work items, 0.6% of what the workers spent, while a representative call each time the body changes (2 to 4 turns an item) adds 640k units ($2.56), 2.8% (`docs/facts/the-representative-wording-test.md`). #637, #878, `crates/core/src/skills/wording.rs`
- Kelpie's issue skill, `skills/kelpie/issue/SKILL.md`, holds the format of an issue an implementer builds from (work.md) and tells the agent to run `shep kelpie issue check <n>` once it files one. It is written as `kelpie-issue` beside `kelpie-wording` and reaches every worker call the same way. No step runs it, so no `[skills]` key turns it off, and `pr = none` keeps it; one that cannot be written is a notice. A test runs the check on its example and holds its parts to the check's. ADR 0018, `crates/core/src/skills/issue.rs`
