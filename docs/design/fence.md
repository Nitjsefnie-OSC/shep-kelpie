# Fence

What a worker may touch, run, write and read, and what only kelpie does. The runner
loop and turns are in workers.md, agent files and harnesses in agents.md.


- Workers start `--setting-sources project` + kelpie-written settings file; maintainer's hooks, plugins, skills don't load (on goose, the call's plugins' skills are linked into its own `config/skills`, `skills.md`). #98, `crates/core/src/profile.rs`
- Kelpie's guard in every worker's settings; `worker.guard_hooks` adds Claude Code hooks; an unresolvable hook stops the runner at start. #108, `runner/guard_hooks.rs`
- Project `hooks` run own commands at `publish`, `commit`, `push`, `handover`, `command`, `write`, `turn_start`, `turn_end`, notices on every harness (`guard_hooks` reach Claude Code alone). ADR 0009, #454, `crates/core/src/hooks.rs`
- Workers run `bypassPermissions` over `main` ruleset + OS sandbox + `kelpie guard` denylist; no auto mode (classifier outages blocked work). `crates/core/src/profile.rs`
- Sandbox and `kelpie confine` hold writes to worktree + build folder, hosts to GitHub, the model, `allowed_domains`. `crates/core/src/profile.rs`
- Guard denies what only kelpie does (merge, ready, `review please`, `gh api`, pushes to `main`, credential reads); a worker's `git fetch` is answered (merge.md); label or ready change kelpie didn't make parks the worker. A goose reviewer, advisor, retro: `--goose --read-only` (agents.md). `crates/core/src/guard.rs`
- Agent files in worktree (`.claude`, `.mcp.json`, `.codex`, `.agents`, `.pi`, `.goose`) fenced, checked before each call; change parks `agent-files` (a review could plant a hook). #98
- Every call runs whole inside kelpie's OS sandbox (`Sandbox` port, `srt` 0.0.77), hooks and MCP included; Claude Code's own sandbox off (macOS can't nest). #128
- `[app.dogs.kelpie.code_graph] enabled` (off) gives reviewers and the triager on every harness codebase-memory-mcp, and `Work` turns too only with `worker` (off: the server's 17 tool definitions ride in every request of a turn and no worker session recorded so far, on Claude Code or pi, has answered one, `docs/facts/mcp-servers.md`): `tools install` fetches a pinned release, `Runner::prepared` names the server in the call's reach and the call's thread (lock let go, a stop ends it) indexes the worktree into `<project>/code-graphs/<issue>` before each call that is given it (UI off, daemon in `<project>/cbm/<issue>`), Claude Code a per-call `--mcp-config` allowing its tools, pi in its home's `mcp.json`, Codex as `-c` overrides, goose as `--with-extension` flags (`skills.md`). Its sandbox writes and binds only there and its `/tmp` scratch, opening the folders above (#948). No binary or failed index: a logged skip and a `doctor` line. Its `install` never runs. #599, #991, `runner/code_graph.rs`, `crates/core/src/ports/mcp.rs` (the servers), `crates/adapters/src/adapters/mcp.rs` (the fence)
- Guard refuses `claude`, `codex`, `pi` as programs (a nested session runs without hooks). `crates/core/src/guard.rs`
- Linux: srt skips `denyWrite` globs, so `fence::deny_write` also lists nested harness folders present at call start (`crates/core/src/fence/nested.rs`); one made during a call is caught by the check against `main` after it. srt also refuses every Unix socket, so no worker reaches the dog's door and `cargo-test` runs unleased; `doctor` says so. #488
- Each harness declares run-code + login files; fence holds all, so no call plants or reads another harness's. #233
- Every call reads the installed sources and docs of its dependencies and toolchains: cargo's `registry/src` and `git/checkouts`, and each rustup toolchain's `lib/rustlib/src` and `share/doc`, each folder from the tool's own variable or its default home. A folder not on the machine adds nothing, and a variable that names a folder relative to wherever the tool was run names nothing, since each call runs its tool from a folder of its own. They are found as they are granted, not once when the runner starts: a machine gains a toolchain and a project gains its first git dependency while the runner runs, and a call rendered before that was granted neither. `Runner::prepared` puts them in the call's read list and the fence's read carve-outs, and a call built without it (a triager, a contribution's security reviewer and its pass reviewers) is granted the machine's own, having no build folder of its own: a contribution is named by its pull request, so `paths.build` of it would be another work item's folder. Claude Code's `additionalDirectories` and the sandbox's `allowRead` both let them through; the write list is untouched, and `CREDENTIALS` still denies what sits beside them. A call that works an item also gets the crates and the standard library of the `CARGO_HOME` and `RUSTUP_HOME` its `build_env` points into the build folder, and kelpie makes each of those folders as it grants it, since a harness judges its grants when the call starts and the call's own tool is what fills them. A build-local rustup home with no toolchain installed is granted as its whole `toolchains` folder, since no toolchain name is known until the call installs one. An answer and a researcher read none of them. #952, `crates/core/src/dep_sources.rs`, `runner/turn/dep_reads.rs`
